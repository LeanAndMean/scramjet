# Terminal verification

Maintainer notes for the retained viewport. User operation, compatibility choices and terminal configuration belong in [Terminal Setup](terminal-setup.md). The records below preserve historical observations; moving them here does not establish acceptance of a newer revision.

## Evidence boundaries

| Check | What it establishes | What it does not establish |
|-------|---------------------|----------------------------|
| Headless TUI and production-composition tests | Parsed emitted text/cells, cursor position, intermediate frames, application input dispatch and flush ordering | Native input delivery, desktop clipboard contents or graphics pixels |
| Transport tests | Framing, timeout and keyboard/mouse mode sequences | Every terminal's delivery behavior |
| Native interaction journeys | Delivered desktop input, clipboard equality, configured terminal behavior and restoration | Every profile, physical trackpad, remote connection or custom component |
| Native graphics journeys | Fresh image pixels, confinement, suppression and restoration on the tested path | Arbitrary custom graphics envelopes |
| Driver self-tests | Required-check sets, failure detection, action receipts and cleanup predicates | A fresh native acceptance run |

The shared headless terminal feeds actual TUI writes into `@xterm/headless`; its `sendInput()` calls the application handler directly. A headless assertion and a desktop check with similar wording can therefore establish different things. Do not remove a native check without identifying the exact duplicate predicate, execution boundary and any calibration, sequencing or cleanup role.

The native journey fixture is `packages/scramjet/tests/fixtures/interactive-viewport.mjs`. Hosted interaction and graphics drivers live in `.github/scripts/terminal-probe.py` and `.github/scripts/terminal-safety.py`; `.github/scripts/test-terminal-fixtures.py` exercises their evidence predicates. `.github/workflows/terminal-feasibility.yml` owns the hosted matrix. Build the runtime before running fixtures, because they load compiled packages. Windows desktop/clipboard execution through `.github/scripts/windows-terminal-probe.sh` requires separate explicit permission.

## macOS native Copy and Paste — 2026-10-08

[Issue #608](https://github.com/LeanAndMean/scramjet/issues/608#issuecomment-6050418989) preserves acceptance of clean commit `3810822bedce066d1c9acfcadc6d02f0c8112412` in [run 37712738710](https://github.com/LeanAndMean/scramjet/actions/runs/37712738710): all 13 jobs passed, with 16 positive reports / 960 required checks and 12 correctly rejected native controls. Apple Terminal 2.14 and iTerm2 3.6.11 ran on macOS 15.7.9 / 24G830, Node 22.23.2, on both ARM64 and x64 without tmux. Each stock terminal/architecture exercised both rebuilt checkout and isolated five-package installations. Stock Copy/Paste shortcuts were unchanged and no `ReportRightClick` override was applied. Apple's existing F8/F9 application-browsing fixture profile did not supply Copy, Paste or wheel gestures. Separately configured right-click journeys remain qualified by their settings.

Actual Command+C had to replace a fresh clipboard sentinel with exact selected Unicode text; selection and live output alone had to leave the sentinel untouched. Actual Command+V had to insert allowlisted multiline/Unicode text between `PREFIX` and `SUFFIX` at an interior caret, with the correct final caret and no submission. Unexpected paste remains consumed and absent from evidence. No-op Copy, copying on selection and consumed-paste controls intentionally produce `passed: false`; only the expected failed outcome plus startup, provenance and successful cleanup establishes `negativeControlRejected: true`.

The native challenges cover unfinished browsing, Copy in another tab during a blocked UI loop, no delayed stale write after recovery, application focus loss, two instances with distinct selections and immediate return-Copy, real registration conflicts and reselection, both external-editor paths with genuine stdin, Ctrl+Z/fg, orderly exit and restoration. Darwin restoration permits only the SDK-identified transient `PENDIN` state bit before a read, then requires exact post-read equality. No configuration flag is ignored or rewritten. Earlier failed attempts, including conflict/focus-transfer defects and a VTE shell-startup oracle failure, remain preserved on the issue; later success does not relabel them.

Desktop automation is privileged, and terminal-child processes inherit hosted-terminal grants. Independently launched receivers used the **installed production native adapter** with Accessibility, input-listening, event-posting and screen-capture preflights all false, made no permission requests, and delivered actual Command+C with successful cleanup. That separate evidence establishes the permission boundary. Stale-ID and failed-release challenges used real Carbon resources with explicitly injected identity/unregister failure; they do not claim a spontaneous OS cleanup failure. This record is not acceptance of every later revision, profile, physical trackpad, remote path or arbitrary extension, nor reproduction of the reporters' installations.

### How the earlier validation allowed the escape

- **Requirement mismatch:** the [#551 plan](https://github.com/LeanAndMean/scramjet/issues/551#issuecomment-5732527548) explicitly accepted Ctrl+C. The native driver tested Ctrl+C, not the macOS user's expected Command+C. The new native action closes a previously accepted behavior gap; it is not evidence of a regression from an earlier Command+C implementation.
- **Paste oracle stopped too early:** the old fixture consumed matching bracketed paste before editor delivery; `desktopPasteRoundTrip` accepted a receipt counter. The [2026-10-06 run](https://github.com/LeanAndMean/scramjet/actions/runs/37527119543) at `0ac415e71f670e90136d6c760c96ccc9b5e053f1` passed while both macOS editor snapshots stayed `Synthetic editorRIGHT-PASTE` and `pasteMatches` changed from 0 to 1. That proves a false-positive acceptance boundary, **not production Command+V failure**.
- **Review boundary:** [PR #560's F9 assessment](https://github.com/LeanAndMean/scramjet/pull/560#issuecomment-5765359890) and [repair](https://github.com/LeanAndMean/scramjet/pull/560#issuecomment-5765969234) removed pasted payloads from diagnostics by preserving interception. That privacy safeguard was meaningful, but it did not establish editor insertion. The current explicitly armed synthetic payload forwards original bytes to the real editor without exposing unexpected paste.
- **Change/release boundary:** PR #560 merged on 2026-09-28 as `ff3a116cbfe12cc2b8d157824d4628d4ac265dfe`, tagged `v0.103.0`. Its checked-in release workflow, and the pre-#608 workflow, allowed tag publication without a native dependency. Historical native success and an observable aggregate were not enforced tag-publication prerequisites. These repository facts do not identify either reporter's installed version or prove which release caused their symptoms.

The reusable native workflow now gates `release.yml` publication at the caller's exact `GITHUB_SHA`, with read-only native permissions, pinned action commits, clean checkout/fixture provenance, installed-candidate records, all required matrix results and native negative controls. Failed, cancelled, skipped, incomplete or malformed required results block publication; no latest-main or ancestor result is consulted. PR checks use their event merge SHA, while a tag reruns acceptance at its own SHA. Package integrity records describe the native acceptance installation, not equality to independently rebuilt publication tarballs. See [release policy](../../../.github/RELEASING.md) for immutable recovery and non-publishing verification boundaries.

The original reporter clarified that Command+V **works**. A separate reported Command+V failure and the unreconfirmed right-click complaint remain unresolved; passing these journeys does not disprove either. Reproduction still needs installed Scramjet version, terminal/macOS version, selection method, profile, SSH/tmux status, custom keybindings/extensions and exact expected/observed behavior. An old process surviving an update is not an established cause.

## Exit retention and right-click latency — 2026-09-28

A user-authorized targeted Windows Terminal 1.24.11911.0 / Windows build 22631 / WSL Ubuntu journey exercised rebuilt packages on the dirty working tree based on `6c06a61812dcc9fc324b570eef35d6bbbd487a43`. An isolated production InteractiveMode used a nonempty model scope, 180 numbered styled history rows, above/below widgets, an editor draft and an underlined footer. It loaded no personal extensions and made no model calls. This was a targeted check, not full-matrix acceptance.

All 12 native predicates passed: calibrated desktop targeting, retention default off, first right-click paste, held-right-button motion paste, terminal-native paste, selector suppression, the actual `/settings` retention toggle, external-editor return, paste after that handoff, orderly exit and termios restoration. Five single-gesture motion pastes inserted exactly once in 13–25 ms from received right press to completed editor insertion; the first paste took about 36 ms. Native paste took about 0.36 ms from received payload to insertion. These are small-sample application-boundary timings, not physical-input-to-pixel latency guarantees. The fixture verified stable synthetic clipboard contents before each gesture; clipboard contention immediately after a change can still add latency.

Inspection of native screenshots confirmed styled history and the complete editor/widget/footer suffix in the restored shell. Parsing the captured application stdout with headless xterm additionally verified every numbered row and the model-scope header exactly once, their ANSI cell attributes, dock order, clean shell styles, no transcript replay between alternate-screen exit/reentry during the external-editor handoff, and zero submissions. Desktop window closure, pointer/focus restoration and absence of leftover matching Windows clipboard workers were independently verified. Deterministic tests cover default-off startup stdout isolation, both docking layouts, settings persistence/overrides/invalid values, graphics placeholders, failed snapshot restoration and clipboard lifecycle/stale-input boundaries.

The latency investigation first measured roughly 440–540 ms of per-request PowerShell startup/setup using clipboard-free output. Reusing PowerShell removed that cost, but the Forms-based reader still took roughly 150–180 ms in the native fixture. Direct Windows Unicode clipboard access with bounded lock acquisition reduced the measured delay without polling or caching clipboard contents. Preliminary runs also exposed a fixture import error, unstable synthetic clipboard seeding (including an empty terminal-native control paste), a focus-loss safety abort and an immediate native clipboard-lock rejection; those failed runs are not acceptance evidence. The final reader bounds acquisition retries before reading data and never repeats an ambiguously failed read.

Reproduction: start an isolated freshly built InteractiveMode with scoped startup and several screens of numbered styled text; calibrate desktop cells, seed and verify synthetic clipboard text, perform one stationary right-click and five press/move/release gestures while recording input and insertion timestamps, compare a native paste, exercise a real confirmation and `/settings` toggle, round-trip an external editor, then exit while scrolled into history. Check the emitted normal buffer and screenshots, termios, owned-window/pointer/focus cleanup and worker termination. Other operating systems, the full native matrix, native image pixels, both external-editor variants together, and job-control suspension were not rerun for this change; images deliberately become labelled placeholders in retained exit history.

## Historical native journey evidence

Detailed successes, failed attempts and exact source commits are recorded in [issue #551](https://github.com/LeanAndMean/scramjet/issues/551) and [PR #560](https://github.com/LeanAndMean/scramjet/pull/560). The [recorded configuration table](terminal-setup.md#native-compatibility-evidence) describes earlier retained-renderer journeys, not blanket acceptance of subsequent changes. Match each claim to the source revision and check names in its report.

The hosted drivers require a zero fixture-exit receipt and terminal restoration; both macOS interaction and graphics drivers separately own and verify closure of their terminal process, windows and shell. The Windows driver independently attempts exit and window closure, then verifies window disappearance, pointer position and foreground restoration; a failed or unverified cleanup cannot pass. Graphics confinement compares fresh image pixels with independent single-row color bands in the safety fixture's above-editor widget and last footer row, preserving their heights and accounting for the leading dock spacer. Calibration uses screenshot pixels rather than default cell dimensions, so display scaling is measured rather than assumed. Graphics suppression checks require post-render action receipts and at least two fresh screenshots over a bounded stability interval. The representative VTE journey includes narrow wrapped editing, autocomplete acceptance and a separate committed-mode startup/promotion, approval, external-editor and suspend/resume journey. No-selection right-click checks outside the editor seed synthetic clipboard text, wait for acknowledged input, and require exact insertion without submission or changes to copy/error/terminal-paste counters over a stability interval; intercepted terminal paste remains payload-free. The current journeys also seed synthetic clipboard text and right-click the actual editor, checking exact insertion and no submission. Selection checks require an updated live footer while selection remains active, exact wrapped-editor copying, and exact copying across the transcript/editor seam in both directions. These predicates replace the older whole-frame freeze expectation; historical successes do not certify them. Linux interaction startup retains its 15-second visible-window requirement and records the owned process, pre-cleanup exit status, last window-search result and bounded failure diagnostics; terminal stdout/stderr and Openbox logs are retained with the artifact. Diagnostic observations cannot turn a failed startup into a pass. Windows desktop/clipboard execution requires separate explicit permission.

## Historical Windows selection comparison

A local comparison on 2026-09-23 used Windows Terminal 1.24.11911.0, Windows 11 build 22631 and WSL Ubuntu, with the existing terminal profile unchanged. A disposable fixture loaded the real compiled InteractiveMode with 1,500 numbered synthetic rows and isolated in-memory settings; no models or personal extensions were loaded. The installed baseline was `b2bb160d7e9f11670915c2f568bc91e3707e3ca7`; the candidate was `575f90bfd847d302eae7f52f901879920f0b8397`, rebuilt only in the development clone. Native desktop events dragged to an edge and then 16 or 100 pixels beyond the window, held there, and released outside. Screenshots, raw fixture stdin, synthetic clipboard reads and terminal-state receipts supplied the observations.

- The installed baseline and candidate `committed` mode accelerated with outside distance. For example, baseline upward screenshots advanced 112 rows over approximately 638 ms at 16 pixels, versus 584 rows over approximately 607 ms at 100 pixels. These are bounded observations, not a calibrated speed curve.
- Candidate `retained` mode stayed near its fixed 12.5 rows/second at both distances. Upward motion reached `ESC[<32;11;1M`, with no additional motion packet revealing outside distance; release arrived as `ESC[<0;11;1m`. Downward motion/release likewise used the bottom cell, row 21. This input path does not supply the distance needed to reproduce native acceleration merely by changing the scroll-rate formula.
- Retained scrolling stopped after outside release. Separate short-selection checks showed highlight persistence through a wheel-scroll round trip, right-click delivery of selected synthetic rows, and left-click clearing in all three modes. They do not establish byte-for-byte copy parity or the entire combined long-selection journey. All three successful runs restored their initial termios state.

An initial accessibility `TextPatternRange.GetText` call crashed the desktop driver; its owned window/button were cleaned up, and the replacement used screenshots rather than that API. A subsequent attempt coalesced mouse movement and did not establish selection; only the paced native-event run supports the observations above. Evidence stayed local. No terminal preferences or installed baseline files were changed. This comparison is not a complete acceptance suite, and retained/native selection parity remains unverified and demonstrably different in acceleration. `committed` remains the existing compatibility option, with its separate mutable-output browsing limitation.

The held-button wheel interaction was compared separately on the same Windows Terminal/WSL path. A press alone followed by stationary wheel input did not start native selection; after a small initial drag, the installed baseline and candidate `committed` mode extended selection on wheel input, while pre-fix retained mode kept only the initial range. The baseline checkout had advanced to `49c1f1209f8129a6dffc84c534da5b1c364ceb14` without changing its TUI implementation. The retained fix now preserves that initial-drag distinction and updates only active transcript selection endpoints. Deterministic checks cover both directions, reversal across the origin, events before repaint, release, boundaries and dock confinement. Three Windows driver cases use wheel-only desktop events and reject intervening drag-motion packets; three more mix horizontal/vertical motion with scrolling in both event orders, reverse direction, and perform a final column adjustment immediately followed by release. All six scroll again after release and independently compare exact Unicode clipboard text. The mixed-input deterministic checks also cover bursts before repaint, dragging after wheel input, final wide/combining-grapheme boundaries, and edge-timer ticks between pointer updates. They exposed and now prevent stale painted-coordinate endpoints and stale edge-timer pointer state, while retaining initial painted-row targeting and dock confinement. All six native cases passed against the rebuilt working tree in a targeted subset with explicit dirty-tree provenance, startup/calibration and restoration checks; the full native journey and other terminal paths were not rerun. These results do not resolve the deferred native-selection differences.
