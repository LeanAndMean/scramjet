## Future refreshes

This snapshot is curated, not the direct output of strict generation: reviewed retentions and scalar price estimates are reconciled outside the generator. The header in `src/models.generated.ts` therefore does not promise regeneration of these bytes from mutable feeds. Strict generation is a safety check, not historical replay or an approval mechanism for missing catalog identities. To accept a removal, establish route-applicable evidence and selection impact, record the provider/ID and disposition here, then reconcile the curated snapshot; do not disable or bypass the exact-loss guard to force a strict write. For estimates, document their applicable source and qualification before updating the snapshot.

Run the generator with `SCRAMJET_MODEL_CANDIDATE=<absolute-new-path>` in an isolated checkout to produce a non-runtime JSON inventory. Missing prices are `null` and listed in `unresolvedCosts`; unqualified dynamic routes/endpoints and missing or zero-usable previously supported optional models.dev sections (including `kimi-for-coding` → `kimi-coding`) are listed in `unresolvedSources`; committed provider/ID pairs absent from the candidate are listed in `unexplainedLosses`. Strict generation refuses any such exact catalog loss before writing; optional sections without previously supported built-ins remain optional. The candidate is never the canonical TypeScript catalog. Normal `npm run generate-models` remains strict: after its safety checks, it can overwrite the curated canonical snapshot and does not reproduce prior manual decisions. It refuses missing/malformed prices or acquisition failures before writing; normal builds never run it. Compare the candidate with the checked-in snapshot and current, route-applicable sources before accepting a new snapshot. Runtime `Model.cost` still requires finite numeric estimates; zero is not a verified-free label. Offline tests check catalog structure and request metadata, not entitlements, provider charges or maximum-request acceptance.
