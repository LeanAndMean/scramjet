# Built-in model catalog provenance

`src/models.generated.ts` is the checked-in runtime catalog. Normal builds do not fetch live feeds. This file records source qualifications and review decisions for the snapshot, not a second runtime authority or a promise that every model is available to every account.

**Removal/selection impact (baseline → corrected snapshot, reviewed 2026-09-23):** The 161 feed/Pi omissions break down by provider as Vercel (41), OpenRouter (34), Cloudflare AI Gateway (25), Copilot (10), Moonshot international and China (6 each), OpenAI (6), Fireworks (5), OpenCode (5), Together (5), Bedrock (4), Azure (3), Google (3), Anthropic (2), Cerebras (2), Groq (2) and Zai (2). The Azure Realtime Responses mapping was removed from an intermediate PR head; it was absent from both committed baseline and final snapshot, and is not part of the 161 removals. Direct Anthropic (2) and direct OpenAI (6) have the provider shutdown evidence cited above; for other groups, the dated candidate plus matching published Pi absence justified removal from the *default catalog*, not a claim that every deployment or account has retired the ID. The 26 explicitly retained routes show that omission alone did not compel removal. Source qualifications vary by route: gateway and OpenRouter listings reflect their own endpoint catalogs; Copilot is subscription/account-scoped, Azure is deployment-scoped, Bedrock may be region-scoped, and direct, Moonshot and Cerebras accounts may differ. No external user's installed selections or privately configured deployments were inspected.

A repository check of removed provider/ID pairs against configured defaults, tests, examples and documented selection paths found one active default reference: `cerebras/zai-glm-4.7`. It is now changed to the surviving built-in `cerebras/gpt-oss-120b` with a catalog-existence test; the old default would otherwise be skipped during automatic provider selection. Saved provider/ID selections for **any** removed pair no longer resolve and fall back to another available model (a warning is printed where enabled). Scoped patterns without matches are skipped; `modelOverrides` do not recreate removed IDs. Users with a still-supported custom deployment must define an explicit `models.json` model with deployment-specific API, context, output and price metadata, then update saved selections/scopes; an override or an alias for an unrelated route is not a migration. A CLI unknown-ID fallback may construct a synthetic candidate but is not endpoint evidence. Repository reference checks cannot establish outside usage, and gateway/region/subscription availability remains unverified.

## Future refreshes

Run the generator with `SCRAMJET_MODEL_CANDIDATE=<absolute-new-path>` in an isolated checkout to produce a non-runtime JSON inventory. Missing prices are `null` and listed in `unresolvedCosts`; unqualified dynamic routes/endpoints and missing or zero-usable previously supported optional models.dev sections (including `kimi-for-coding` → `kimi-coding`) are listed in `unresolvedSources`. Strict generation refuses such supported-provider source loss before writing; optional sections without previously supported built-ins remain optional. The candidate is never the canonical TypeScript catalog. Normal `npm run generate-models` remains strict and refuses missing/malformed prices or acquisition failures before its canonical write; normal builds never run it. Compare the candidate with the checked-in snapshot and current, route-applicable sources before accepting a new snapshot. Runtime `Model.cost` still requires finite numeric estimates; zero is not a verified-free label. Offline tests check catalog structure and request metadata, not entitlements, provider charges or maximum-request acceptance.
