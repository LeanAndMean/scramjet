# Built-in model catalog provenance

`src/models.generated.ts` is the checked-in runtime catalog. Normal builds do not fetch live feeds. This file records source qualifications and review decisions for the snapshot, not a second runtime authority or a promise that every model is available to every account.

The review standard is proportional to observed use: direct Anthropic, OpenAI and OpenAI Codex receive closer route-specific checks; other providers use validated live metadata and upstream Pi as corroboration, with concrete conflicts examined. Pi's different per-provider topology, protocol selection, pricing tiers and account routes are not automatically adopted. Missing source prices are not evidence of free usage: 1,284 missing scalar fields were estimated from Pi only when provider, ID, API and base URL matched exactly; 32 used an existing Scramjet same-route value. These are **usage estimates**, not billing truth. The 30 new records still lacking an applicable estimate were excluded rather than serialized with `null` or guessed zero. ## Future refreshes

Run the generator with `SCRAMJET_MODEL_CANDIDATE=<absolute-new-path>` in an isolated checkout to produce a non-runtime JSON inventory. Missing prices are `null` and listed in `unresolvedCosts`; unqualified dynamic routes/endpoints are listed in `unresolvedSources`. The candidate is never the canonical TypeScript catalog. Normal `npm run generate-models` remains strict and refuses missing/malformed prices or acquisition failures before its canonical write; normal builds never run it. Compare the candidate with the checked-in snapshot and current, route-applicable sources before accepting a new snapshot. Runtime `Model.cost` still requires finite numeric estimates; zero is not a verified-free label. Offline tests check catalog structure and request metadata, not entitlements, provider charges or maximum-request acceptance.
