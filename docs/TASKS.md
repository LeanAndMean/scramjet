## Current state (2026-10-30)

- `scramjet-rs agent` is a usable interactive coding agent through Proxy (`gpt-6-luna` by default; Claude models through the Messages API, see below): read/write/edit/bash tools, project AGENTS.md/CLAUDE.md context, resumable sessions, retries of transient provider failures, streamed reasoning summaries and replies, and an inline prompt editor (bracketed paste without sending, multi-line input, editing keys, history from the session, type-ahead flushed before `--ask` questions). Text typed during a turn is hidden and kept for the next prompt. Tool results show a short preview: the bash output tail, a numbered diff for edits. While a command runs for more than a second, its last five output lines update above the `running` line. A dim status line says what the agent waits for, with elapsed seconds (`thinking`, `preparing <tool>` while a call streams, `running` after a second of tool time). Reasoning summary parts are separate paragraphs; Ctrl+T, at the prompt or during a turn, hides the reasoning that streams next behind a dim `Thinking...` line or shows it again, with `Thinking blocks: hidden`/`visible` on the status line or under the prompt, as in Scramjet (during a turn Ctrl+T is the terminal's quit character with `NOFLSH`, so text typed ahead stays queued; Ctrl-C still discards it; `f673b7f`). Streamed reasoning and replies wrap between words, with list items continuing under their text and their markdown styled (bold, code spans, headings, fenced code blocks). The retry wait counts down on the status line. `!command` runs a shell command from the prompt without a model turn, shows its last 20 lines and adds Scramjet's ``Ran `command` `` message to the context for the next prompt; `!!command` leaves it out (2026-10-31). `/new` starts an empty session without exiting; `/compact [focus]` replaces all but the last ~20k tokens with a summary, as Scramjet's compaction does, ending with the files read and modified in all compacted history (`<read-files>`/`<modified-files>`, carried across compactions in the session file, `c158976`), and the conversation also compacts by itself after a turn that used more than the window minus 16,384 tokens, before a new prompt when the last response's count plus an estimate of the items after it (a failed or cancelled turn's tool output) passes that (`95e334c`), or once per turn after a context-overflow error before sending the request again (status `compacting`); `/model` lists the endpoint's models and `/model ID` switches to one (other models' encrypted reasoning is not replayed; each switch is saved at once as a `model_change` line, so `--continue` resumes the last model used or switched to, `38a3979`). Tool calls run without approval questions, as in Scramjet (`ec9d2f4`); `--ask` asks before every bash command and every write or edit outside the project. Its questions show control and text-direction characters as escapes and repeat a bash command only when it has more than one line (the call line shows the first); answering `a` allows all later tool calls until exit. Ctrl-C at an approval question cancels the turn (recorded for the model as cancelled before the call ran). Requests carry the session id as `prompt_cache_key`. Tool paths starting with `~` are in the home directory. The usage line after each turn ends with how full the context was at the last response (`context 53k/1.1M (5.0%)`, the window from Proxy's `/api/model-cards`). Verified live on scratch projects, including a `--version` change to a clone of this repo.
- Claude models (2026-10-30): models whose Proxy card lists only `anthropic-messages` (or, without a card, ids starting with `claude-`) go to `/v1/messages` (`src/agent/messages.rs`): the agent's Responses request is converted (system prompt and last block marked for caching, adaptive summarized thinking for Claude 4.6+, `max_tokens` from the card), and the Messages stream back into Responses items (signed thinking as `reasoning` items with `signature`, `redacted`), so sessions switch freely between GPT and Claude. `/model` lists Claude. Verified live through Proxy (5 requests): an Opus 5.5 read-tool turn (cache read on the second request), the same session continued on gpt-6-luna and then on claude-haiku-5-5 with a bash call and a signed thinking block. Signed thinking replay across tool calls works live (16 requests in a claude-haiku-5-5 practice run, 91% of input read from the prompt cache). Claude before 4.6 gets budget thinking (`6bc3c55`). Use claude-haiku-5-5 for live Claude checks (user, 2026-10-30: much cheaper, output quality does not matter for tests), as gpt-6-luna for GPT.
- The original first-provider goal is met: two fresh `coding` invocations through Proxy wrote a haiku, then wrote and ran a Python reader whose output matched the file.
