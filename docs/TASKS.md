## Known issues

Not scheduled; fix them when they matter.

- In printed output (`-p`, piped input), a reply's calls running at the same time print in call order, each once the calls before it ended, so a quick call after a slow one prints `took` up to when it printed, not when it ended (`AgentUi::tool_result` carries no time; the full screen records it as the result comes).
- `bg` after Ctrl-Z during a turn stops the agent again at once: the SIGTSTP handler restores the turn's terminal mode, which a background job may not do (Scramjet's TUI cannot run in the background either). In `-p` output on a terminal, a reply rewritten in place after a lossy stream (`text_rows`) still counts rows from before a stop.
- Every start writes a session file before any prompt (Scramjet writes none before the first reply). It goes when the session moves to another before anything was said in it (`/resume`, `/new`, `/fork`, `-r`), but stays on quitting or while another process has it open (its `--continue` took it), and `/resume` hides it while `--continue` picks it when it was written last, which keeps the `/model`-switch-before-a-prompt behaviour agreed on 2026-10-30.
- `/resume` lacks Scramjet's scope (Tab: this folder or all), sort (Ctrl+S: threaded, recent, relevance), named-only (Ctrl+N) and path (Ctrl+P) toggles, Ctrl+Backspace for delete, and its rows' colors (the current session in the accent color, named ones in the warning color); its status after a delete stays until the next key, where Scramjet's goes after 2-3 seconds.
- The GPT overflow wording through Proxy is unverified (needs a request over 1.05M tokens; Scramjet's OpenAI pattern is `exceeds the context window`). deepseek-v4.1-flash's gateway answers an overflow with HTTP 400 `This model's maximum context length is 327680 tokens…` (its card says 320000).
- `claude-haiku-4-5-20251001` runs without thinking: its Proxy card has no `reasoning` field ("no reasoning control" in Proxy's card schema), though Scramjet's registry marks it as reasoning.
- With credentials hidden, the main agent's bash still shares the host's processes, `/tmp`, `/run` and session (so that `setsid nohup … &` outlives a command). Other processes' `/proc/<pid>/environ` and `/proc/<pid>/root` are closed to it (its own user namespace; Permission denied, checked), but servers running outside act for it with everything visible: an ssh-agent (`SSH_AUTH_SOCK`), a tmux server on a socket outside `${TMUX_TMPDIR:-/tmp}/tmux-UID` (`tmux -S`, or under a `TMUX_TMPDIR` other than scramjet-rs's own; its path shows in `/proc/net/unix`, and bubblewrap cannot mount over a socket), and, not tried, Docker's socket and WSL interop (`cmd.exe`, `/run/WSL`); and through the controlling terminal TIOCSTI (allowed before Linux 6.2; WSL runs 5.15) could type a `!` command. Only subagents' sandbox has its own processes, `/tmp`, `/run` and session.
- Subagents' bash cannot start tmux in its private `/tmp` (`error creating /tmp/tmux-UID (Permission denied)`): the sandbox mounts over the user's socket directory there too, as it must when `TMUX_TMPDIR` is elsewhere. It worked before dbe6f2d; if it matters, give the sandbox a `TMUX_TMPDIR` of its own in `/tmp`.
- The full screen renders a running turn's part again from all its events at each frame (at most every 16 ms). Measured on a release build for a turn of 150 calls with 400-line outputs: 4 ms a frame cut, 100 ms with Ctrl+O (61,000 lines). Ctrl+O and Ctrl+T keep the view at the same part and line within it, which can move within a long turn.
- A `!` command run during a turn in the full screen shows its block under the conversation with at most 20 of its last lines, fewer on a short screen (each block about half of it), not expandable with Ctrl+O until the turn ends (Scramjet's view scrolls instead, and expands it); several run during one turn each keep a block there until it ends. A `!` typed while the session itself runs one (no turn) runs alongside it, where Scramjet refuses a second.
- A built-in command typed during a turn in the full screen waits for the turn's next request, which can be minutes away while a tool or subagent runs (Scramjet runs `/session`, `/name`, `/model` and `/copy` at once); the dock shows it as `Command: …` meanwhile.
- Undo is Ctrl+- (byte 0x1f, which Ctrl+_ also sends), as Scramjet's. Windows Terminal's default actions are believed to take Ctrl+- for the font size (not checked); Ctrl+Shift+- would then reach the editor.
- Skill discovery does not honor `.gitignore`, `.ignore` or `.fdignore` files in skill directories, as Pi does; it skips only hidden entries and `node_modules`. Pi's `skills` patterns (`!`, `+`, `-`), `--skill`, `--no-skills` and `enableSkillCommands` are not supported.
- The model takes a `scramjet_next_step_selection` record for a call it made: nothing tells it the harness writes them (Scramjet's instructions do not either; they mention only model-change notices). In the live check on a contrived session, claude-haiku-5-5 called it a call "that isn't in my tool list", and again (in its reasoning, "that was a mistake earlier") when a next step switched it in from gpt-6-luna. If models dwell on it, say in the instructions that the harness records next-step choices.
- `/settings` writes the `autonomy.yaml` files without Scramjet's update lock (`autonomy.yaml.lock`), so a change Scramjet saves at the same moment could be lost. It also rewrites a file it changes in Scramjet's layout, without its comments, as Scramjet does.
- A completed Responses stream with no output items fails as malformed (`src/http/responses.rs`, `self.items.is_empty()`), where Scramjet's client takes it as an empty reply, which now gets a status check. Not seen from Proxy's GPT routes; Claude's empty replies (Scramjet's #381) come through Messages and are checked.
- Mach 12's commands still tell the model to report `blocked` or `incomplete`. The refusal steers it on, and claude-haiku-5-5 read the schema and reported `completed` with an honest summary instead, but a command set written for this lifecycle would not need the detour; Mach 12 lives in Scramjet's repository.
- The cost leaves out compaction and branch summary requests (Scramjet's footer does too; their usage is not saved), and failed attempts, whose usage is not known. Cache writes are priced at the card's one cache-write rate, as Proxy prices them, though the Messages route asks for 1-hour caching, believed billed at 2× input (Anthropic's 1-hour rate; not checked for Bedrock) rather than the 5-minute 1.25× the cards give.
- A failing test can leave its directory in `/tmp`: the `autonomy`, `commands`, `agent_cli::clipboard`, `agent_cli::editor` and `agent_cli::file_search` tests remove theirs only at their end, where the other agent tests use the `agent::tests::ScratchDir` drop guard.
