## The command line

```sh
scramjet 'Explain src/main.rs'            # a session that starts with that prompt
scramjet -p 'Explain src/main.rs'         # print the answer and exit (-p - reads stdin)
scramjet @shot.png 'What is wrong here?'  # send a file or an image with the prompt
scramjet -c                               # continue this project's latest session
scramjet -r                               # choose a session to resume
scramjet -p -r 1795 'And the tests?'      # follow up in the session whose id starts 1795
scramjet --model opus:high                # the newest Opus, at high effort
scramjet --list-models                    # the providers' models
scramjet list                             # the command sets and skills loaded here, and problems
scramjet lint --strict ~/repos/mach12     # check a command set before using it
```

Other main options: `--thinking LEVEL` (or `--effort`), `--models PATTERNS` (the models Ctrl+P cycles through), `--no-session` (save nothing; or Claude Code's `--no-session-persistence`), `--resume ID` (as Claude Code's: the session `--session ID` names, with `-p` too; an ID is digits and dashes, or a `.jsonl` file, else the word is a prompt), `--fork-session` (with `-c`, `--resume ID` or `--session`, continue a copy in a new session, as `--fork` does), `-n NAME` or `--name NAME` (as Claude Code's: name the session, new or resumed, as `/rename` does), `--ephemeral` (also keep the settings' changes, models last chosen, output rates, quotas and agents approved for the run only; logins and the providers' model lists are still saved), `--bare` (read nothing from your own directories but the settings, `models.json` and `auth.json`: no context files, `SYSTEM.md` or skills of `~/.config/scramjet`, `~/.agents/skills`, `~/.claude/skills` or the home directory, no commands of `~/.claude/commands`, no agents of your own or of `~/.claude/agents`; what the settings list and the project's own still load), `--max-turns N` (with `-p`, stop with an error before a model request past the Nth, as Claude Code's), `--max-budget-usd AMOUNT` (with `-p`, stop with an error before a model request once AMOUNT dollars are spent, as Claude Code's; responses of unknown cost are not counted, with a notice), `--output-format json` (with `-p`, print the run's result as one JSON object on stdout, as Claude Code's: `subtype` (`success`, `error_max_turns`, `error_max_budget_usd` or `error_during_execution`), `is_error`, `result`, `num_turns`, `session_id`, `total_cost_usd`, `usage`; the replies then go to stderr; or `stream-json`, a JSON line per reply block and tool result as they come, as Claude Code's, then that object), `--ask` (ask before shell commands and writes outside the project), `--permission-mode MODE` (Claude Code's: `plan` starts in plan mode, `bypassPermissions` or `--dangerously-skip-permissions` turns `--ask` off, `dontAsk` is `--ask` with `--permission-prompts none`, the other modes change nothing), `--allowedTools LIST` (tools whose calls `--ask` lets run without asking, as Claude Code's, MCP servers' as `mcp__SERVER__TOOL` or `mcp__SERVER`; an MCP tool named keeps the MCP tools in `--tools`' list; its rules for one tool's calls, `Bash(git *)`, are not kept: those calls ask as without them), `--permission-prompts none` (as Claude Code's: what `--ask` would ask about is refused, and the model told so), `--tools LIST` (the only tools, Claude Code's names such as `Bash` or `Glob` taken too), `--disallowedTools LIST` (tools left out of the run's, as Claude Code's; its rules for one tool's calls, `Bash(git push *)`, and MCP servers' tools are refused, as Scramjet cannot leave them out), `--system-prompt` and `--append-system-prompt`, `--no-directives` (leave out the `# Scramjet` orientation and Scramjet's directives, which otherwise follow the context files and skills; or the `directives` setting `false`), and `--project DIR`. `scramjet --help` lists every option in a line, and `scramjet --help-all` each in full, with the keys and the built-in commands.

The agent has all seven coding tools by default (read, bash, edit, write, grep, find, ls), then the harness's own (command status, questions, delegation, subagents, a todo list, model switch, suggestions, GitHub publications, MCP search); `tools` in `/settings` switches each on or off, saved as Codex's table of those changed (`"tools": {"switch_scramjet_model": false}`), and a list there (`["read", "grep"]`) names the tools on, all the harness's own when it names none of them; `grep`, `find` and `@` file completion are built in, with ripgrep's libraries, so neither ripgrep nor `fd` is needed. Tool calls run without asking; [the sandbox](configuration.md#the-sandbox) and `--ask` are how to limit them. A question the agent asks with options (select or confirm) ends with a "Type something." row: Enter or typing there opens a field, and Enter sends what you typed to the agent as your answer; Escape cancels the question. For work of several steps the agent keeps a checklist (`todo_write`, as Claude Code's `TodoWrite` and Codex's plan): each change shows as a list of boxes, the item being worked on in bold, those done struck through, and `/todos` shows the list as it stands; a compaction keeps it, and over ACP it is the session's plan. The agent reads a web page with `web_fetch` (Claude Code's `WebFetch`): Scramjet fetches the URL, gives a page as Markdown (headings, lists, links made absolute, code and tables; scripts and styles dropped) and a text, JSON or XML file as it is, the first 2000 lines or 50KB of it, the whole saved to a file the agent can `read`; it cannot log in or run a page's scripts, and it is refused while the network is off.

## In a session

The conversation fills the terminal above the prompt, which stays usable while the agent works: Enter then steers the agent before its next request, Alt+Enter queues a follow-up for when it would stop (one sent too late for the turn goes as the next prompt), and Escape interrupts, putting what it did not take back in the prompt. Built-in commands such as `/model`, `/settings` and `/autopilot` run at once while it works. Ctrl+O expands tool output, Ctrl+T hides or shows reasoning, Shift+Tab changes the effort (`/effort LEVEL` sets it by name, `/effort` lists the levels), Ctrl+P the model. `!cmd` runs a shell command and gives its output to the agent; `!!cmd` keeps it out. On Windows it runs in bash when found, else PowerShell, or in the shell `/settings` chooses (`defaultShell`: `bash`, `powershell` or `cmd`).

The mouse scrolls and selects, and Shift with the arrows, Home or End (Ctrl+Shift+Left/Right by word) moves a selection's end, and Shift+PgUp or Shift+PgDn moves it a page (with the prompt empty, Shift+Up, Shift+PgUp, Shift+Left, Shift+Home or Ctrl+Shift+Left starts one at the end of the conversation shown); in the prompt they select its text, which typing replaces. A right click or Ctrl+C copies the selection (with Copy on select in `/settings`, on by default on macOS, a selection made with the mouse is copied as soon as it is made), a right click without one pastes, and Ctrl+V (or Alt+V) pastes a clipboard image as the path of a file it is saved to. [TERMINALS.md](../TERMINALS.md) says what your terminal does with copying, pasting and these keys, such as the keys it keeps for itself.

Up and Down recall this session's earlier prompts. Ctrl+R, as in Claude Code and Codex, lists the prompts of this folder's other sessions too, newest first, each once, with the session it is from; typed words narrow the list to the prompts holding each of them, Tab shows every folder's, and Enter puts the one chosen in the prompt for you to edit or send (Escape leaves your draft as it was).

The prompt you are typing is kept with the session, a few seconds after each change and as Scramjet exits (Ctrl+C or Ctrl+D, the terminal closing), in `~/.local/state/scramjet/drafts/`: resuming the session (`-c`, `-r`, `/resume`) brings it back with its last 200 undo steps (Ctrl+_, that is Ctrl+Shift+-, or Ctrl+- where the terminal lets it through, and Ctrl+Z on native Windows) and what undo took back (Ctrl+6 redoes it), and sending it removes it. Ctrl+C clears the prompt, which undo brings back, but leaving with Ctrl+C or Ctrl+D right after keeps the prompt it cleared. A new session whose prompt was never sent leaves no session file, only that prompt, which `-c` continues while no newer session was written.

Misspelled words in the prompt are underlined (American English, with common developer words such as `repo` and `config`), leaving paths, identifiers, short capitals and `!` commands alone; your own words go one a line in `words.txt` beside the settings file, and Spelling in `/settings` turns it off.

`/context` shows how much of the model's window each part of the context takes, and `/system-prompt` the instructions the last request sent, with each tool's definition. The agent can run a command in the background (bash's `run_in_background`, as Claude Code's), such as a server or a long build: it returns at once with the task's number and the file its output goes to, runs on across turns until it ends, the agent stops it (`task_stop`) or Scramjet exits, and the agent is told how it ended, with the end of its output, before its next request: within the turn running, where a notice says so (`Background task 1 exited with code 0.`), else with the next prompt. On the full screen, one that ends by itself while the agent waits for you starts a turn at once, as Claude Code's does: its prompt says how it ended (`Background task 1 exited with code 0.`), and what you were typing stays in the editor; one you stopped waits for your next prompt. While any runs, the footer says how many (`1 background task`). `/tasks` lists them, each running or how it ended, and `/tasks stop N` stops one (`/bashes`, and Codex's `/ps`, too). On the full screen the list's Enter shows a task's output so far, from its end (its last 2,000 lines), or, while it runs, asks whether to show it or stop it. `/goal CONDITION` gives the agent a goal, as Claude Code's: it works toward it, and after each turn that ends by itself the model is asked whether the conversation shows the condition met; until it does, the reason goes back to the agent as the next prompt. The goal ends once met, or once a check finds it can never be; Escape stops the work and keeps it, `/goal` says it, `/goal clear` clears it, and a new or resumed session starts without one. `/loop [INTERVAL] PROMPT` sends the prompt now and then again each interval while the full screen waits for you, as Claude Code's: `/loop 5m check the deploy`, `/loop /mach12:pr-review 12 every 2h`, the interval as `30s`, `5m`, `2h` or `1d`, 10 minutes when none is given. One that comes due during a turn runs once the turn ends, once, and the next an interval after that; Escape stops a run, not the loop. The footer says `loop every 5m`; `/loop` says the loop and when it runs next, `/loop stop` ends it, and a new or resumed session, or 7 days, end it too. `/plan` starts plan mode, as Claude Code's and Codex's: the agent explores and proposes a plan without carrying it out. `write` and `edit` are refused, and in a sandbox commands and subagents run read-only; without one, the agent is only asked to run commands that change nothing. The footer says `plan mode`, and after each turn that ends by itself the full screen asks whether to implement the plan: yes ends plan mode and sends "Implement the plan.", Escape or no keeps planning. `/plan PROMPT` starts it with that prompt, `/plan off` ends it. `/usage` shows what is left of each provider's quota where it says, and what the saved sessions spent.

## Sessions are trees

`/tree` (or Escape twice on an empty prompt) goes back to any earlier point and continues from there, optionally summarizing the branch left behind; `/fork` and `/branch` continue in a new session. `/rewind` (`/checkpoint`, `/undo`), as Claude Code's, goes back to before one of the prompts on the way to here: it puts back the files `write` and `edit` changed since (removing those they made), moves the conversation there as `/tree` does with the prompt in the editor, or both; what commands and subagents changed stays as it is. `/rewind N code` or `/rewind N conversation` does one at once, and in line mode `/rewind` lists the prompts. `/resume` picks a session to continue (another folder's continues in that folder), `/compact` summarizes the conversation so far, `/export` writes it as a self-contained web page, or as text to a path ending in `.txt` (without a path the full screen asks, as Claude Code's does, whether to save the page, copy the text or save it), and `/copy` copies the last reply (`/copy N` the Nth-latest; on the full screen a reply with code blocks offers each of them, or the whole, unless `copyFullResponse` is on); in `/resume`, sessions that fresh-session next steps chained show their summaries, and Ctrl+X shows chains flat, threaded or folded. To tell sessions running side by side apart, `/rename NAME` (or `--name NAME` at the start) names one; the name is saved with the session and goes with `/branch`, and a new session starts without one.

Sessions are saved under `~/.local/state/scramjet/sessions/` (or `--session-dir`). A session's file shows what was sent and received; it holds the whole conversation and what the agent read, so look through it before attaching it to a report. `/resume` keeps what it lists of each project's sessions in `~/.local/state/scramjet/session-cache/`, read again from a session's file once that changes; it holds their prompts and replies (what `/resume` and Ctrl+R search); a removed session's entry goes at the next `/resume`, and a removed directory is rebuilt. When many sessions are not in it yet, the full screen's list shows the newest at once and fills in as the rest are read ("reading N more" in its title); its search covers those read so far.

## Keys

`/hotkeys` (or Codex's `/keymap`) lists every key; Enter on an action changes its keys (you press the new one, and what else it means is shown first). `/keybindings` opens the file they are saved in, `~/.config/scramjet/keybindings.json`, which gives an action other keys in Scramjet 1's format and with its action ids (`{"app.message.followUp": "ctrl+q"}`); `[]` leaves an action without keys. `tui.viewport.pageUp` and `pageDown` are Page Up and Page Down; Scramjet adds `tui.viewport.top` and `bottom` (Ctrl+Home, Ctrl+End) and `tui.select.first` and `last` (Home, End). `/hotkeys` writes the file as you change keys; after editing it yourself, `/reload` reads it again. `/` lists the commands and skills as you type.
