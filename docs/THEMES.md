# Look and themes

User decisions on the scrollbar, the editor's box, themes, the look and the theme editor, from `/rs:steer` on 2026-11-04 and 2026-11-06. Moved here unchanged from [DESIGN.md](DESIGN.md#look-and-themes-2026-11-04) to keep that file within the tools' read limit.

User decisions from `/rs:steer` on 2026-11-04 ([the task list](TASKS.md) holds the order; the theme editor is an exception to building beyond Scramjet only once the daily driver is solid):

- **Scrollbar.** Scramjet's: the rightmost column, shown while the conversation is taller than the view, clickable and draggable. It is a visual aid to where the reader is.
- **The editor's box holds only the prompt and its completion list.** Notes and messages go to the status row above it.
- **Themes.** Exact colors (24-bit, with a 256-color fallback), and a built-in "Terminal colors" theme that keeps today's 16 terminal colors. A theme may set the main background; otherwise the terminal's own background is used, asked of the terminal so that contrast can be scored. Underneath, a theme is a palette of main colors plus every role, each following one of them or holding its own exact value. The default theme follows the terminal's background as Scramjet's does: `scramjet-dark` on a dark or unknown one, `pi-light` on a light one; a chosen theme wins (2026-11-06). At start the full screen asks the terminal only for its background, as Scramjet does; its text color and 16 colors when the theme list opens (2026-11-06).
- **A distinct look**: a visual language for reasoning, tool calls, prompts and replies. Picked at the steer of 2026-11-06 from captured screens of one scripted session: `panels` is the default look and `header` the default banner; the other looks and banners stay offered in `/settings`. Panels follows Scramjet's spacing of boxes, without copying Scramjet's interface: a tinted padding row above a call's header, under it and at the bottom, as user messages have; one left edge for all text; a failed call's output in its normal color on the error background. Its own marks stay: the outcome on the header, the time there, the tool's name before its arguments, `›` on prompts. Polishing it means comparing it with Scramjet on the same scripted session, judging each difference.
- **A theme editor in `/settings`** that lets users with no artistic background discover a theme they like, quickly, over a live preview of a sample session showing every UI element: choose 1–5 main colors and a harmony that fits that number (monochrome, complementary, analogous, triadic, split-complementary, square, rectangle…, each described in one plain line); roll a whole theme in it (text, dim text, borders and block backgrounds derived at readable contrast and tinted toward the main colors, every role filled) until it is close; lock colors you like, so a roll changes only the others and locked colors anchor the harmony; set any element to an exact color or reset it to follow its main color, all roles one view away; bump toward the harmony in small steps, or contrast up or down. Undo and redo cover rolls and bumps. From 2026-11-06: choosing another harmony keeps the colors, changing only the score and what a bump aims at; Alt+Up and Alt+Down reorder the main colors; a theme started from another stays recognizably itself through contrast and background changes (its colors shift, not jump to newly derived ones); the main background's lightness steps lighter or darker than the derived one, keeping its tint from the first main color.

  Scores read at a glance (2026-11-06): each score's quality shown by color (red bad to green good, or a background), with labels saying what they measure, capitalized alike, not a bare number or words after each; the loop tries forms on screen and picks one, with `Choice:` trailers. Harmony is scored on hue only, in a perceptual space where lightness and chroma stay fixed as the hue turns; each template hue is a sector, the template's rotation fitted to the palette or anchored by locked colors, each color counting by its chroma (grays barely count); repeated bumps converge to a perfect score. A contrast guard keeps every text/background pair within a band neither too faint nor too harsh, nudging lightness as little as needed after each step, or the color skips it; contrast bumps change only lightness. Colors with a meaning (errors, success, warnings, diff added/removed) keep their hue ranges, pulled toward the harmony only within them; each can be set by hand or have its range switched off. The color wheel defining "opposite" (artist's or perceptual) and the contrast formula (WCAG 2's ratio or APCA) are the loop's choices, judged by the randomizer's results, with `Choice:` trailers.
