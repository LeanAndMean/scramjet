### Protocol evidence and qualifications

Parent-fetched primary pages on 2026-10-28, following bounded public-only search/WebFetch research; claims below were independently checked in returned primary page text, not just snippets or the research conclusion:

- [Responses streaming events](https://developers.openai.com/api/reference/resources/responses/streaming-events): `response.completed` is emitted when the response is complete; `output_item.done` marks an item done. For reasoning: “Use the reasoning item from the corresponding response.output_item.done event when passing it as input to a subsequent request.” Added encrypted data may be incomplete. No whole done/terminal JSON equality guarantee was found in the inspected references; absence of a guarantee is not proof that arbitrary differences are harmless.
- [Responses create reference](https://developers.openai.com/api/reference/resources/responses/methods/create): encrypted content is optional string/null; completed reasoning from DONE is the streaming replay source. Function/reasoning status is optional; output-message status is specified. Assistant phase is optional `commentary`/`final_answer`/null and must be preserved. The bounded fetched portion includes the applicable input/output item and inclusion definitions; this is not a full reference audit.
- [Reasoning guide](https://developers.openai.com/api/docs/guides/reasoning): stateless applies to `store:false`/ZDR; encrypted reasoning is returned by default; “The API still accepts the legacy reasoning.encrypted_content value in include for compatibility, but doesn’t require it.” Preserve reasoning, function-call and result items since the last user message “untouched.”
- [Conversation-state guide](https://developers.openai.com/api/docs/guides/conversation-state): “For stateless reasoning-model requests, preserve every item in the response’s output array.” Complete replay keeps encrypted reasoning and assistant phase intact.

These are current general OpenAI contracts, not a deployed Proxy/`openai/gpt-6-luna` attestation, encryption-validity proof, or reconstruction of ordinal4. Examples and optional-field absence do not establish continuation sufficiency or permit required context deletion. No route call or private capture/ledger access is needed to implement the offline contract. ### Completion and replay decisions

1. Independently validate each supported complete DONE and terminal item. Require the same response identity, output count/order/index identity, item ID/type, assistant role, ordered part types and exact text/summary, and function name/call ID/exact argument bytes. JSON-object arguments remain duplicate-free; semantically equivalent but different argument strings do not redefine the invocation. All items/parts/arguments must actually finish; contradictory explicit status, terminal error/incomplete details, failed/incomplete terminal, missing DONE, body/deadline failure or missing required durability cannot expose an executable envelope. Keep optional completed-status presence flexible for function/reasoning items; do not weaken explicit completion contradictions or generalize that exception to message status.
2. Replace deep equality with a bounded comparison at the supported schema locations. Annotation arrays and logprob metadata on output-text parts are non-execution/replay-authority metadata; differences there need not reject otherwise identical material text. Retain bounded opaque entries rather than interpreting citations/probabilities as capabilities; annotations, when supplied, remain arrays, and logprobs may be absent/null/array as a tolerated telemetry representation, not an assertion that all are required by the protocol. Compare phase and encrypted reasoning as continuation data, not ignorable metadata: validate phase's supported enum/null shape and encryption's string/null shape; differing concrete values are contradictions. Unknown differing fields, including fields nested outside these narrowly identified exceptions, remain `Unsupported`, not guessed harmless or malformed; equal opaque values survive. Unsupported namespaces/routed/asynchronous call semantics stay non-executable. No broad metadata allowlist or exhaustive provider schema rewrite is needed.
3. Select an entire validated item without merging, stripping or rewriting it. Prefer DONE when equivalent. A whole terminal item may supply missing concrete phase for a message if it retains all concrete DONE continuation values and matches every other material/opaque predicate. Prefer the complete DONE reasoning item, as explicitly documented; terminal-only reasoning encryption is `Unsupported` rather than substituted for a missing completed streaming replay source. DONE-only reasoning encryption is retained even if terminal omits/nulls it. For other continuation data, choose a whole snapshot containing all observed concrete values; if no one allowed snapshot preserves them, refuse. Never resolve two conflicting concrete values by source priority. This is a client source-selection policy, not a claim that the protocol promises asymmetric enrichment. Optional phase absent/null in both snapshots remains supported.
4. For this stateless reasoning-continuation boundary, a selected reasoning item without string encrypted content is `Unsupported` (legal optional schema, unavailable supported continuation), not malformed, zero usage or permission to drop the item. Strings stay opaque, with no guessed alphabet, cryptographic validation or field maximum. No reasoning item is itself required when the provider returns none. Explicitly request the documented `include:["reasoning.encrypted_content"]` alongside existing `store:false`: redundant in current OpenAI docs but a supported acquisition request, not a new effort/context setting or proven Proxy behavior. Add no other reasoning options.
5. Preserve all selected output items in output-index order and their complete raw values; replay every item with the original user context, tool definitions and exactly correlated result. The request constructor remains the byte/work and call/result correlation boundary. The runtime remains admission/cancellation/result authority; parser success is not tool approval. No provider-backed coding loop or effect execution belongs here.
6. Bound the **selected canonical envelope**, including response identity and wrapper serialization, not only the terminal snapshot. Removing equality invalidates the old assumption that terminal and replay budgets are interchangeable. Preserve existing item/frame/wire limits and allocation ceilings. Complete next-request serialization, including tools, opaque reasoning and escaping, must fit the unchanged 16384-byte request budget or return `ResourceLimit` before submission/reservation/POST, without clipping any required history or redefining advertised model limits. Accepted individual envelopes do not guarantee that their combined conversation fits.
